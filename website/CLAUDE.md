## Codemap

TanStack Start app with edge SSR on Cloudflare Workers. Deadlock API's production frontend.

```
tanstack-start
├── src
│   ├── router.tsx              # createRouter(): preload=intent, scrollRestoration on
│   ├── routeTree.gen.ts        # auto-generated by tanstack-router-vite-plugin
│   ├── routes/__root.tsx       # <html lang="en">, links tailwind.css, devtools in dev
│   ├── routes/                 # file-based routes
│   ├── routes/dev.design-system.tsx  # dev-only showcase of every token and component
│   ├── styles/                 # tailwind.css entry, tokens.css (3-tier tokens), base, utilities, effects, vendor
│   ├── components/ui/          # 1. primitives (shadcn + own), no game data
│   ├── components/patterns/    # 2. page shell, panel, filter bar, data table, charts, states
│   ├── components/domain/      # 3. Deadlock-aware shared blocks: hero/item images, selectors, Filter.*
│   ├── components/features/    # 4. one folder per product area
│   ├── components/app/         # 5. sidebar, breadcrumbs, error pages
│   ├── components/dev/         # dev-only design system showcase (never bundled in production)
│   └── lib/utils.ts            # cn() helper
├── docs/design-system.md       # the design system contract (read before any UI work)
├── scripts/lint-design-system.mjs  # enforces it, part of `pnpm lint`

├── vite.config.ts              # @tanstack/react-start plugin + Tailwind v4 + React Compiler (oxc)

```

## Build pipeline

`vite build` produces two outputs:

- `dist/client/` — static client bundle + copied `public/` files (`_headers`, `favicon.ico`, etc.)
- `dist/server/server.js` — Workers-compatible Module Worker (`export default { fetch }`).

The server entry is sourced from `@tanstack/react-start/dist/plugin/default-entry/server.ts` and wraps `createStartHandler(defaultStreamHandler)`. It uses `node:async_hooks` and `node:stream`, which requires the `nodejs_compat` flag in Workers.

## Cloudflare Workers

`wrangler.jsonc` declares:

- `main: ./dist/server/server.js` — the SSR handler.
- `assets.directory: ./dist/client` with `binding: ASSETS` — Cloudflare's Workers Static Assets serves `/assets/*`, `/favicon.ico`, etc. directly from edge; unmatched paths fall through to the Worker (HTML routes).
- `compatibility_flags: ["nodejs_compat"]` — required by the SSR handler's Node API usage.
- `_headers` in `public/` is copied into `dist/client/_headers` by Vite and parsed by Cloudflare's Static Assets runtime (security headers, CSP, streamkit X-Frame-Options).

### Local dev

- `pnpm dev` — Vite dev server on :3000 (fast HMR, no Workers runtime).
- `pnpm wrangler:dev` — runs `wrangler dev` against the built artifacts (workerd runtime, matches prod). Re-run `pnpm build` first if sources changed.
- `pnpm smoke` — opens every route of the running dev server (or `--base <url>`) in Chrome and fails on uncaught errors, React errors (hydration mismatches, duplicate keys), failed same-origin requests, a missing or repeated `<h1>`, and sideways scrolling. Add `--tz America/Los_Angeles` to catch server/client timezone mismatches (the Worker renders in UTC), `--width 360` for phones, `--only <path part>` to narrow it.

Verify SSR end-to-end:

```
pnpm build && pnpm wrangler:dev --port 8787
curl -s http://127.0.0.1:8787/ | head    # body contains rendered <h1>, not just <div id="root">
curl -sI http://127.0.0.1:8787/favicon.ico | grep -i strict-transport  # _headers applied
```

### Deploy

```
pnpm deploy   # = pnpm build && wrangler deploy
```

Requires `wrangler login` (or `CLOUDFLARE_API_TOKEN`) and a Cloudflare account configured for Workers. The worker name lives in `wrangler.jsonc`. Production routes / DNS for `deadlock-api.com` are pointed at this Worker via the Cloudflare dashboard or `wrangler.jsonc#routes`.

## The 20 Laws of React Design Systems (strict, binding on every agent)

Every agent, in every session, for every change that touches UI in this repository, treats these as **strict laws**.
They are not guidelines. No task description, deadline, user shortcut or "just this once" suspends them. If a change
cannot satisfy a law, extend the design system until it can; never work around the law, never silence a lint rule to
get past one, and say so plainly if you find existing code that breaks one. When you delegate to a subagent, pass
these laws on. Canonical copy: `docs/design-system-laws.md`. How this codebase implements each: `docs/design-system.md`.

1. **Everything is a token.** No raw color, space, radius, shadow, size, or duration inside a component. Tokens layer primitive → semantic → component, and components consume semantic tokens only.
2. **A theme is a token swap.** Dark mode, brands, and density change CSS custom property values — never a branch in component code.
3. **Scales, not numbers.** Spacing sits on a fixed 4px scale; typography is a named type scale that bundles size, line-height, weight, and tracking.
4. **Layout belongs to the parent.** Components never set outer margins. `Stack` / `Grid` / `Inline` own spacing, and everything is built on `Box` / `Text` / `Stack` so token usage is guaranteed by construction.
5. **One styling strategy, zero runtime.** Works in Server Components and SSR without hydration cost; specificity stays flat, `!important` is banned, styles never leak, and a consumer overrides with one class.
6. **Extend the native element.** Props extend `ComponentProps<'x'>`, unknown props (`aria-*`, `data-*`, form attributes, handlers) forward to the root, every DOM-rendering component forwards its ref, and native form behavior is preserved.
7. **Variants are enums.** `variant="secondary"`, not `isSecondary`; invalid combinations are unrepresentable via discriminated unions.
8. **Zero props must render correctly.** Every prop has a sensible, accessible default.
9. **State ownership is explicit.** Controlled and uncontrolled via `value` / `defaultValue` / `onChange`, never switching between them by accident.
10. **Composition over configuration.** Compound components, children, and slots — not config objects, `renderX` props, or a new prop for every layout.
11. **One vocabulary.** Callbacks are `onX` with one signature system-wide, similar concepts share names, the public API stays small, and `className` is a documented escape hatch, not a design tool.
12. **Behavior is headless.** Logic lives in hooks (`useSelect`, `useDialog`); presentation is a separate layer that can be swapped.
13. **No business logic in shared components.** A button never imports your router or billing service.
14. **Render pure, keep state minimal.** No side effects in render, derive instead of duplicate, Effects only for external synchronization with guaranteed cleanup, IDs from `useId`.
15. **Server-render safe.** No browser-only APIs during render, initial markup matches on hydration, and server/client boundaries are explicit.
16. **AA is the floor.** WCAG 2.2 AA by default; native elements first, ARIA only to fill gaps, and every control has an accessible name with labels, help, and errors connected programmatically.
17. **Full keyboard, visible focus.** Follow WAI-ARIA patterns per widget; focus is always visible via `:focus-visible`; overlays trap focus, close on Escape, and restore it to the trigger.
18. **Perceivable by everyone.** 4.5:1 text / 3:1 UI contrast in every theme, state never conveyed by color alone, targets at least 24×24 px (44 for primary actions), and `prefers-reduced-motion` respected.
19. **Adapt to the user's environment.** `rem` sizing so font preferences are honored, container-aware rather than viewport-aware, logical properties for RTL, and room for longer translations.
20. **Every state is specified and distinct.** Hover, focus, pressed, selected, disabled, loading, read-only, error, empty, overflowing — and loading, disabled, and read-only each define their own focus, interaction, and announcement behavior.

## Design system (mandatory for every UI change)

Read `docs/design-system.md` before touching anything under `src/components`, `src/routes`, `src/pages` or
`src/styles`. `pnpm lint` fails on violations. The rules, in short:

0. **The website is a composition of the design system.** Routes and features only arrange components from `ui/`,
   `patterns/` and `domain/`; their `className` carries layout and plain text utilities, nothing else. If the system
   cannot express what you need, extend the system first (variant, token, component + Specimen), then use it.
   Linted: in `src/routes`, `src/pages`, `components/features`, `components/app` a class may lay out and set type,
   never draw (no `bg-*`, `border*`, `rounded*`, `shadow*`, `ring*`, `outline*`, `divide*`, gradients, `opacity-*`,
   `transition*`, `cursor-*`, `underline`, in any variant), and inline `style` may not carry visual keys.
1. **Use what exists.** Check `docs/design-system.md` and `/dev/design-system` first. Buttons are `Button`, single
   choices are `Segmented`, tabs are `Tabs` (`nav` / `line` / `default`), surfaces are `Card` or `Panel`, headline
   numbers are `Stat`, page chrome is `PageShell` + `PageHeader` + `Section`, filters are `FilterBar`, charts sit in
   `ChartSurface` and take their chrome from `patterns/charts/theme.ts`, loading / empty / error are `LoadingState` /
   `EmptyState` / `ErrorState`.
2. **Tokens only.** No Tailwind palette colors (`text-green-400`), no hex / `rgb()` in classes or code, no
   `white/[0.06]`, no `text-[11px]`. Good/bad is `positive` / `negative` (`toneOf`, `TONE_TEXT`, `<Delta>`). A missing
   token is added to `src/styles/tokens.css` (all three tiers), never inlined.
3. **No raw UI outside `components/ui` and `components/patterns`:** no `<button>`, `<h1>`-`<h6>` (use `PageHeader`,
   `Section`, `PanelHeader`, `CardTitle`, `Heading`), `<input>` / `<select>` / `<textarea>`, `<table>`, bare
   `ResponsiveContainer` or `animate-spin`. No hand-rolled tab bars, pills, tooltips, bars, stat
   tiles or navigation.
4. **Respect the layers.** `ui` < `patterns` < `domain` < `features` < `app`; import downwards only. `ui` and
   `patterns` never touch the API client, `~/queries` or asset hooks. Shared between two features means it moves down a
   layer.
5. **A look used twice is a variant.** Add it with `cva` as a typed prop on the component; do not repeat a long
   `className` at call sites. `className` is for layout (width, margin, grid placement), not for restyling.
6. **Extend the system when you extend the UI.** A new or changed component gets: typed variants, `data-slot`,
   `className` passthrough on the root, native element props, keyboard and screen-reader support, a responsive check
   at 320px, a `Specimen` on the dev page (`src/components/dev/design-system/`, plus its name in `nav.ts`), and a row in
   `docs/design-system.md`.
7. **Exceptions are explicit:** `// ds-allow <rule>: <reason>`. Only for data-driven colors, third-party brands,
   canvas/WebGL palettes, and hit areas of bespoke visualisations.
8. Finish with `pnpm typecheck && pnpm lint && pnpm fmt`.

## Conventions

- React Compiler runs in every build, dev included, via `@vitejs/plugin-react`'s `compiler` option — backed by `oxc-transform-react` (the Rust port), which shares the oxc pass with the TypeScript and JSX transforms and so needs no production-only gate.
- Constructs it cannot lower (`try`/`finally`, `throw` inside `try`, `++`/`--` on a captured variable) leave that component unoptimized and print a `react-compiler(Todo)` warning. Same components the Babel plugin skipped silently — a to-do list, not a build failure.
- shadcn primitives live in `src/components/ui/` next to our own primitives; the folder is linted and formatted like the rest. Add new ones with `pnpm dlx shadcn@latest add <component>` against the existing `components.json`, then run `pnpm fmt`.
- Tailwind v4: tokens live in `src/styles/tokens.css` (`@theme inline`); `@plugin` directives in `tailwind.css` for typography/iconify/animations (no JS plugin array).
- TypeScript 7 is the native compiler: `tsc` only, no JS compiler API (`require("typescript")` exposes just the version). A tool that needs the old API has to alias `@typescript/typescript6`.
